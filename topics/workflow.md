# Workflow

## Rules

- When a task is impossible as stated, stop and ask for clarification before reverting any changes. Do not silently roll back and mark the task done.
- When presenting a plan (e.g. via ExitPlanMode or any plan-style writeup), put the narrative first -- steps, rationale, file/function references -- and move all literal code (snippets, diffs, full file contents) into a single section at the very bottom, under a clear heading (e.g. "## Code changes"). Keep the top skimmable so it can be reviewed without scrolling past code; keep the code section in the same order it's referenced above.
